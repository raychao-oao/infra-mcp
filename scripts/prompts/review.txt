**程式碼審查任務**

**審查範圍**（僅限靜態分析）：
1. 程式碼語法正確性
2. 邏輯錯誤和潛在 bug
3. 安全性問題（如 SQL injection、XSS 等）
4. 程式碼品質（可讀性、維護性）
5. 最佳實踐遵循

**重要限制**：
- 你**無法執行程式碼或測試**
- 只能進行**靜態程式碼分析**
- 不要因為無法測試而判定 FAIL
- 若程式碼邏輯和語法正確，即使無法測試也應判定 PASS

**判定標準**：
- STATUS: PASS - 程式碼無明顯錯誤、語法正確、邏輯合理
- STATUS: FAIL - 發現明確的語法錯誤、邏輯漏洞、安全問題

**重要**：請在回應的最後一行明確輸出審查結果：
- 如果沒有明顯問題，輸出：STATUS: PASS
- 如果發現明確錯誤，輸出：STATUS: FAIL
