### 文檔狀態說明
- **current**: 當前有效的文檔
- **deprecated**: 已廢棄但保留參考的文檔
- **draft**: 草稿狀態，尚未完成的文檔

### 影響範圍說明
- **前端**: 僅影響前端系統
- **後端**: 僅影響後端系統
- **資料庫**: 僅影響資料庫結構
- **全系統**: 影響多個系統模組

## 📏 檔案增長控制機制

### ✅ 允許建立新檔案的情況

1. **新功能模組開發**
   - 條件: 獨立功能且相關程式碼 > 200行
   - 範例: 新增AI推薦算法模組
   - 檔案命名: `功能名稱-implementation.md`

2. **重大架構變更**
   - 條件: 影響多個系統模組的架構調整
   - 範例: 從REST API轉換為GraphQL
   - 檔案命名: `架構變更-migration-plan.md`

3. **版本里程碑記錄**
   - 條件: 重要版本發布 (v1.0, v2.0等)
   - 範例: 系統正式上線記錄
   - 檔案命名: `version-milestone-v2.0.md`

4. **專業領域分離**
   - 條件: 不同技術領域需要獨立文檔
   - 範例: AI算法、資料庫優化、前端架構
   - 檔案命名: `領域名稱-技術文檔.md`

### ❌ 禁止建立新檔案的情況

1. **微小功能修改**
   - 條件: 程式碼變更 < 50行
   - 處理方式: 更新現有相關文檔
   - 範例: 小幅UI調整、參數微調

2. **重複主題內容**
   - 條件: 已有相似功能或主題的文檔
   - 處理方式: 擴充或更新現有文檔
   - 範例: 已有登入功能文檔，不可再建立類似文檔

3. **臨時記錄和測試**
   - 條件: 臨時筆記、測試紀錄、除錯記錄
   - 處理方式: 使用臨時檔案或加入現有文檔
   - 範例: 臨時的API測試結果

4. **個人備忘錄**
   - 條件: 非共享的個人開發筆記
   - 處理方式: 保存在個人目錄或工具中
   - 範例: 個人的開發心得、學習筆記

#### 檔案合併標準
**強制合併情況**:
- 內容重複度 > 70% 的檔案
- 同一功能的多個版本文檔 (保留最新版)
- 檔案大小 < 5KB 且功能高度相關的檔案
- 超過6個月未更新且內容已過時的檔案

**合併程序**:
1. 識別需要合併的檔案
2. 分析內容重疊和差異
3. 建立統一的新文檔
4. 更新所有相關連結
5. 將舊檔案移至 05_archive/
6. 記錄合併原因和時間

## 📝 內容撰寫標準

### 語言和風格
- **語言**: 使用繁體中文，專業術語保持一致
- **風格**: 簡潔明確，避免口語化表達
- **語調**: 客觀中性，重視準確性

### 技術描述標準
```markdown
## 技術描述範例

### ✅ 正確範例
```python
# 建立資料庫連接
connection = pymysql.connect(
    host='localhost',
    user='evo_user',
    password='password',
    database='evo_ai_mvp'
)
```

**說明**: 使用 pymysql 連接器建立 MariaDB 連接，適用於生產環境。

### ❌ 錯誤範例
```python
# 連資料庫
conn = some_db_lib.connect(host, user, pwd, db)
```

**問題**: 程式碼不完整、註解不專業、無法直接執行。
```

## 🔧 檔案命名規範

### 檔案名稱格式
```
[功能領域]-[具體內容]-[文檔類型].md

範例:
hourly-scheduling-implementation.md    # 小時制排班實作
database-migration-guide.md           # 資料庫遷移指南
api-modification-plan.md               # API修改計畫

```

### 文檔類型標準
- `implementation`: 實作文檔
- `guide`: 操作指南
- `plan`: 規劃計畫
- `design`: 設計文檔
- `reference`: 參考資料
- `status`: 狀態報告
- `analysis`: 分析報告

### 功能領域標準
- `system`: 系統相關
- `database`: 資料庫相關
- `api`: API相關
- `frontend`: 前端相關
- `backend`: 後端相關
- `hourly-scheduling`: 小時制排班
- `rule-management`: 規則管理
